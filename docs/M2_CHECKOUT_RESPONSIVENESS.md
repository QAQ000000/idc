# 选购响应优化与库存展示

## 实施契约（2026-11-10）

本批只改选购响应、脱敏耗时和库存观察；不购买商品、不操作上游资源，不迁移数据库或重启 M2 Worker。资金结算、下单及 Worker 前置预检、原请求键恢复继续保留。

商品及本地配置并行读取，读取完成即显示可编辑表单；报价独立显示“正在核价”，有效报价前禁止提交。选配变化同步清除旧确认，400ms 防抖；同一页面最多一个在途核价，结束后只发送最新且已停顿的选择。旧响应不得覆盖配置、价格或库存，离页取消等待与前端请求。取消浏览器请求不承诺取消已开始的上游执行。

目录和选配页共用库存展示：本地销售配额与上游观察分别显示。有货、售罄、未限制数量、暂未确认四种上游状态；可靠数量和核对时间才展示。上游未启用库存控制时 qty=0 不是售罄；查询失败与明确缺货使用不同提示。Redis 仅缓存短期观察，读取失败／观察过期显示暂未确认，不触发远端目录逐项查询或绕过预检。

库存观察独立于商品配置快照、报价指纹和任务载荷。原库存配额不被上游数量覆盖；报价／导入时所得上游观察进入短期缓存，不写商品销售配置。缺货返回独立业务码，网络／协议异常仍需重新核价；缓存不是预留或履约保证。

魔方插件只记录登录、配置读取、价格计算的阶段名、耗时及传输结果，不记录域名、账号、Token、请求参数或响应体。先测量再决定 Token 复用，本批不增加登录缓存。

## 验收计划

- 独立 HTTP／MySQL／Redis：库存四态、失效／Redis故障降级、售罄与查询失败、未控制且数量0、库存变化不影响原报价确认；配额和历史冻结不改，Worker缺货预检继续拒绝。
- 浏览器：延迟报价时表单可见可编辑，连续修改只发最后选择，在途时不堆积、旧响应无效、有效报价前不可提交，原键恢复保持；目录与选配页一致，手机与竖屏平板无溢出。
- 只读真实核价：分别记录登录／配置／价格计算耗时；不将夹具耗时或浏览器取消误报为上游性能改善。

## 真实只读耗时及Token决定

同一已配置Provider、商品389的既有1 IP低规格配置，连续进行3次驱动级只读预检；MySQL会话设置TRANSACTION READ ONLY，不调用商品保存、下单、收款或开通。均返回首期／续费¥38。当前代码日志只含白名单阶段／毫秒／HTTP状态／传输结果，不包含上游域名、Token或原始响应。

| 阶段 | 3次范围 | 中位数 |
| --- | --- | --- |
| 登录 | 1118.5–1420.7ms | 1119.2ms |
| 配置读取 | 1479.0–1539.9ms | 1483.4ms |
| 价格计算 | 1124.2–1131.2ms | 1128.7ms |
| 整次预检 | 3729.6–4090.1ms | 3737.7ms |

登录约占三成，短期复用可能节省约1.1秒，但其余两段仍约2.6秒；本批先落实可编辑表单与请求合并，不增加Token缓存及失效／连接隔离规则。此处样本只有3次，不是生产分位数，也没有以不同环境的截图时间宣称服务端已经提速。脱敏原始记录在 `/tmp/jianyun-checkout-live-timing.jsonl` 和 `/tmp/jianyun-checkout-live-stages.jsonl`。

## 兼容与运行边界

变更原因是旧页面等待全链核价、逐次输入堆积，以及库存语义混合；影响原CatalogService、快照预览服务、PreflightResult和魔方插件、目录与结账页、接口／插件／前端契约及路线图。PreflightResult只追加默认null的stock，旧驱动无需空实现；公开响应增加可选观察。新错误码保留HTTP409，其他报价与原checkout_key恢复不变。

不新增库存表／列、配置项拆表或任务；仍27表，无schema或增量迁移。Redis键按应用／库／Provider／远端商品隔离，5分钟过期且目录一次MGET批读；新增的upstream_stock观察不写入config_cache，不进入preflight签名、driver_context、历史账单或Outbox。原始Schema中已有的上游字段不是展示库存事实，显式刷新整份商品快照仍遵循原重新确认规则。目录没有近期观察时如实显示未知，通过选配核价更新，不增加全目录远端扫描。

本轮未导入商品、创建M2账单、付款或开通；未重启M2 Worker及共享服务，未完成M2整页实际手测。部署前依原运行规程核对归属并让HTTP／前端／原Worker同版，不能仅凭本地开发服务热加载宣称运行接入完成。563零库存门禁保持，真实销售仍按用户决定暂不购买。
