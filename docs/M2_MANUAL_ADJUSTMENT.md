# 手工变配补差与后续续费价联动

## 范围与确认

管理员已经在原上游完成变配后，当前启用超级管理员在原实例详情填写完成依据、目标周期价，先预览再显式确认余额结清。财务可读，客服／运维不返回价格或资金。此入口不调用上游、不改变资源绑定、销售配置、起租时间、到期日或原冻结续费价，不创建 upgrade Outbox；不表示已自动核验实际规格。

## 首批计价规则

只结算包含预览时刻、且结束于实例当前到期日的**单个已付并确认履约的原始周期**。新购取交付起租时间和自然月／年第一到期日；续费取原账单冻结的 base_due_date／target_due_date，并核对原资源、Provider、账期、金额及成功 renew。不能从当前覆盖价逆推本期实付价，也不能从月末到期日倒减一个月。

新购首期金额必须等于冻结周期价；包含无法拆分初装费时拒绝自动补差。多期预付、过期权益、历史改期导致原周期无法证明、未确认履约或未知旧 upgrade 均拒绝，并提示人工核账；不猜价格、不改历史权益。当前覆盖价只用于展示未来价格，不能替代计价依据。

补差＝max(目标周期价−本期已覆盖周期价, 0)×剩余秒数÷本期实际总秒数。先乘后除，纯 BC 十进制计算，最后半分向上到分；实际自然月／年支持月末与闰年。5分钟预览冻结 UTC 计价时刻，必须在原周期内结算；不把本期价差加到未来每期价格上。

同一原周期既往人工补差必须有已付 upgrade 和同事务不可修改审计，已覆盖周期价保持最高已结清价；降价不退款、不降低已覆盖基数，之后升回原覆盖价不重复收费。新周期重新使用该期原续费账单金额。零补差仍保留已结清账单和人工完成审计，不制造零额扣款流水或收款凭证。正补差计为云消费，增加 total_spent；当前返佣非零的商品不开放本入口。

## 事务与幂等

短效签名预览绑定管理员、实例及原账单／任务／改价与补差审计版本、新周期价、完成依据和计价时刻。结清需确认已完成变配与余额划扣，并提交唯一 request_key；重放原请求返回原账单，不重新计价。过期／被篡改预览、角色变化、归属变化、并发续费或改价均要求重新预览。

实例优先锁→原任务／退款／服务门禁→原账单与预览版本→角色重核→补差账单 unpaid→paid CAS、余额／流水／余额凭证、消费累计、未来覆盖价、作废原未付续费单并释放周期标记、人工完成审计全部同一事务。余额不足或任何写入失败整体回滚。旧收银台迟到实收继续原凭证幂等入钱包，不能执行旧价续费。普通支付接口不接纳人工 upgrade。

## 展示与兼容

复用 invoices.type=upgrade、price_snapshot 与 checkout_key/hash、transactions、payment_records、admin_audit_logs；不新增表、DDL 或迁移，仍27表。人工完成事实保存原账单快照及同事务审计，客户和财务详情按二者关联显示“人工变配已结清”，不能把普通无任务账单当成功或补造 success 任务。依据只向财务／超级管理员展示，客户只看金额与结清结果。

修改冻结契约的原因是将已人工履约的补差与未来自动变配分开，避免重复执行上游操作。涉及账单展示、实例管理、未来改价版本、支付／生命周期／API／数据库说明和路线图；原自动变配仍未实现。实施与隔离／页面验证结果在完成后补记；真实客户补差与正式环境不在本批验收范围。
