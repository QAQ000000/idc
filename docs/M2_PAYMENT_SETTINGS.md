# 易支付配置后台

## 范围与契约

本批提供 `/admin/payments` 与 `GET/PATCH /api/v1/admin/payment-settings/epay`，仅当前启用的超级管理员可读写。复用 `system_settings.payment.epay`、原易支付插件和收款结算服务，不增加表、迁移、渠道或自动退款。首次可保存为停用，密钥 AES-256-GCM 加密且不回显；更新必须显式 keep/replace、携带 expected_version，并与脱敏审计同事务。

“启用”仅准许创建新支付尝试，不控制历史回调。停用后仍验签并按原归属、凭证唯一键、账单CAS和钱包规则结算，不能丢弃迟到／额外实收。余额付款不受易支付开关影响。

配置保存和收银认领先锁同一配置行。收银先取得锁并提交支付尝试时，该尝试有效，即使表单在停用后返回；停用先提交时，新请求409且不创建尝试。插件生成表单在认领事务内完成，不发网络请求；生成失败整体回滚。回调无需此行锁，商户身份因已有尝试而不可修改。

任一易支付尝试（包括pending／failed）存在后，网关地址、商户号和密钥永久锁定；付款方式、本站通知／返回地址和新收银开关仍可版本化修改，不重写旧表单。版本包含是否已有尝试及审计序号，故首次收银会使旧编辑版本过期。CLI安装器复用相同首次配置校验与行锁，不能覆盖既有配置。禁止直接改库绕过这些约束；密钥轮换与历史身份兼容另批设计。

## 页面、权限与恢复

渠道状态、密钥配置／身份锁定摘要、保存和只读核对入口前置；详细参数按需展开。初始失败不开放表单。非敏感草稿仅在页内保留；有草稿或未决请求时离开提示。

409、丢响应或不可信成功先GET核对，不自动PATCH。版本不变的未知请求继续阻断；当前版本已变化且公开值匹配可确认当前配置。密钥替换未知不能仅凭“已配置”确认，须显式核对采用当前版本；已锁定时采用服务器商户身份，不能保留旧身份草稿重提。密钥离焦点／视口、折叠、后台化、pagehide、路由离开或失权时清除，提交先固定请求再清输入。

## 验收计划与边界

隔离MySQL／HTTP检查首次配置、权限、版本竞争、审计回滚、密文与输出脱敏、历史身份锁定；停用前已创建的新购／充值／取消单回调、重复及额外实收；用行锁控制两个顺序，验收停用／创建收银竞争。浏览器检查手机／平板入口、折叠、密钥清除、409和落库丢响应只读恢复。不操作M2支付配置、不真实扣款、不启用工单邮件。本地完成后补充实际结果。

## 兼容、复杂度和未验证边界

变更原因是共用enabled检查会丢旧款，事务外配置读取无法界定并发停用与商户替换。影响PaymentService、独立PaymentSettingsService、CLI安装器、纯本地支付插件契约、两个后台页面的恢复算法与导航；原回调／账单结算HTTP协议、凭证唯一身份、CAS／账本／Outbox／资源归属保持。

不增配置历史表、同步任务、第二支付渠道或退款机制；增加配置行锁、三项身份锁定和同事务脱敏审计。版本包含现有审计ID，避免同值配置ABA；密钥不新增摘要／副本。已有数字PID只规范为相同字符串，不切换商户。共享测试库过去通过删除配置换夹具商户，现先仅在jianyun_test中把先前epay夹具收款移入每行独立的测试渠道命名空间，保留账本关联事实，避免放松真实服务的历史身份锁；该工具不进入业务入口。

仅完成开发与隔离验收；M2真实支付配置未修改，没有真实新收款／退款、Worker重启或正式部署。M2工单邮件启用和真实收件继续独立，密钥轮换与历史回调兼容仍需另行设计。现有M2进程及数据保持。
