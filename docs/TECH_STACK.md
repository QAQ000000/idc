## 2. 框架与领域职责

当前自建适配的证据、保留理由、框架替代成本及库存缓存试点统一维护在[框架复用盘点](FRAMEWORK_REUSE.md)，不在本文复制清单。

Laravel 承接通用基础设施；定价、账单、钱包、退款、返佣、实例生命周期和未知结果恢复继续由领域服务按现有契约实现。HTTP Controller 负责接收、校验和调用服务；具体 Provider、支付、通知与验证码插件通过契约和注册器装配，核心不直接依赖具体插件。

迁移必须保留以下约束：

- 正常云消费的账单 CAS、余额扣款、资金账本、收款记录及 Outbox 入库使用**同一物理数据库连接、同一事务**。现有 PDO SQL 可以通过框架管理的连接适配，不要求全部重写为 ORM。
- 数据库事务与外部调用分开；业务幂等、任务令牌/租约和人工核验门禁继续按 [TASKS_OUTBOX.md](TASKS_OUTBOX.md) 执行。Laravel 普通队列、`afterCommit` 或任务重试设置均不能替代持久 Outbox 和未知结果调查。
- Redis 唤醒可以丢失，MySQL 扫描必须兜底；Redis 锁或租约到期不能解除实例业务占用。
- 用户/管理员身份隔离、API 归属校验和模拟登录限制继续保留。现有 Token 与 AES-256-GCM 密文格式需要兼容；引入框架认证或加密组件前核准格式、主密钥及存量数据的转换，不能直接替换后丢失解密能力。
- 后台 Worker 为独立受管理进程；逐任务隔离用户、请求与事务状态，并验证崩溃、重启及过期执行者回写。HTTP 使用 PHP-FPM 也不免除 Worker 的常驻状态管理。

现有文档中的 `Database::transaction()` 等示例表达领域事务边界，框架适配时统一连接和事务管理，不要求永久保留自建路由、Redis 协议客户端等基础代码。

## 3. 数据库与插件兼容

完整 DDL 继续以 [database/schema.sql](../database/schema.sql) 为唯一事实来源，当前 **8 张核心表、27 张物理表（含 1 张框架迁移登记表）**基准及保护触发器继续有效。Laravel 默认迁移中的用户、会话、缓存、队列等表逐项审查，不能重复建立用户/账本/任务模型；合适的基础设施数据可使用已选 Redis。

M0 采用 Laravel 标准迁移运行器及 migrations 表登记版本，审查记录见 §7。若确需新增迁移元数据或其他物理表，必须先完成领域/基础设施边界审查，并同步数据库设计、权威 DDL、接口影响及路线图，不能以框架默认行为跳过表数基准。最初选型提交未修改表；本轮 M0 的版本登记及下单幂等字段变更见 §7。

旧站数据迁移工具仍是**独立上传旧站的导出插件**，输出指定目标版本的 SQL 数据库备份，通过通用 MySQL 工具恢复空库。它不成为 Laravel 模块或简云插件；目标 schema 变化后重新生成导出包并演练，详见 [MIGRATION_RUNBOOK.md](MIGRATION_RUNBOOK.md)。

## 4. UI 与交付节奏

统一使用 Element Plus 标准组件与一套布局；前端保持 Vue Router、Pinia 和现有 REST API 组织，不因采用 Laravel 自动切为 Inertia 或增加第二套前端。Tailwind 不是首版必需依赖，少量业务样式按需添加。组件、状态、权限与响应式规则见 [FRONTEND.md](FRONTEND.md)。

首条真实链路以一个上游、一个商品和一个支付渠道完成“购买 → 收款 → Outbox → 真实交付 → 实例查看”，带必要管理及异常核验入口。随后扩展续费与日常运营，再逐项增加上游和增值功能。各阶段使用真实接口完成必要页面；界面精修排在业务闭环之后，财务安全及生产门禁不因缩小范围而降低。

## 7. M0 实施中的 schema 边界审查

采用 Laravel 标准迁移运行器；新增 `migrations` 仅记录迁移文件及批次，不承载用户、资金或任务事实。原 26 张业务/支撑表保留，加 1 张框架版本登记表，全库基准调整为 27 张，不安装默认 users/cache/jobs/sessions 表。schema.sql 仍是完整空库结构，PHP 版本迁移描述已有库的增量；历史 001/002 SQL 必须先按其规程执行，不由本轮猜测旧库状态。初始迁移仅接受空库或经基线检查的旧 MVP 库；不提供旧站迁入功能。

下单幂等在现有 invoices 增加可空 checkout_key / checkout_hash 和 (user_id, checkout_key) 唯一键；请求键区分大小写，摘要使用 APP_KEY 派生 HMAC，不存明文密码。旧客户端不带键保持兼容，新前端固定同一次提交的键；同键不同参数返回 409，取消后重放仍返回原取消订单，新购买使用新键。有限库存未付占用每用户最多 3 笔，正常即时余额支付不受此占用限额影响。


M0 兼容及验证记录（2026-11-07）：现有 API 路径、Token、AES-GCM 与金额字符串保持兼容；方法不匹配采用框架标准 405（旧路由 404），auth/me 增补 client 角色字段，详见 API 兼容记录；登录 bcrypt 移出钱包行锁，锁内重检凭证/状态；拒绝 NUL 注册密码。框架替换原路由、RESP 客户端及事务执行器，CLI 保留薄别名。执行隔离 MySQL/Redis 回归与私有 PHP-FPM 配置缓存前后验证，并实测必要前端页面。未提供通用 Worker、真实支付或旧站迁入能力；其安全门禁继续有效。`migrations` 的 down 和下单幂等字段 down 均拒绝自动破坏性回滚，已有库变更先备份并逐项审阅。

验证证据：`php tests/unit.php` 15 项、`php tests/plugins.php` 15 项、`python3 scripts/test_integration.py` 119 项及私有 FPM 两轮探测通过；前端 lint/typecheck/build 及 Chrome 交互通过。FPM 与 MySQL/Redis 均为测试独立进程，测试后清理；未替换系统共享服务。
