# M2 客户实例重装契约

## 范围与协议证据

同一 Vue 实例详情页提供可选重装能力；只有驱动明确声明、原账号资源归属与账期一致、服务有效且无任务／资金占用时才允许提交。首批仅支持魔方 `dcimcloud`、`module_button.control` 明确声明 default/reinstall、上游 `/host/header` 返回有效 `cloud_os` 的实例。其他模块、裸金属、手工资源均不推断支持。

协议依据是旧财务 `Host::reinstall`、`DcimCloud::reinstall` 与已留存商品 14 的 header：`/provision/default` 接受 id/func=reinstall/os/is_api=1/format_data_disk=0；云模块不接受客户自定义密码，而是上游生成。首批密码模式明确显示为上游生成，不收集或忽略自定义密码，不额外发起重置密码。镜像 ID 为财务返回的选项 ID，不能替换为底层 OS ID。数据盘固定“不请求格式化”，不开放全盘清空；此参数不是数据无损承诺，客户须备份。

## 提交与可靠执行

GET `/api/v1/instances/{id}/reinstall` 只读能力、镜像与最近 10 条任务；签发 120 秒确认令牌，绑定客户、实例、资源／状态版本和能力摘要。POST 同路径要求镜像、原令牌、request_key 和 `confirmed_system_disk_erase=true`。页面先选择镜像并勾选备份／系统盘清空，再弹窗二次确认。禁止代登录提交。

HTTP 网络读取在事务外；提交锁实例，重新检查版本、归属、客户／上游启用、所有排队任务和 TaskGate，再写 invoice_id=NULL、action=reinstall、max_retries=0。payload 冻结原绑定、镜像、能力摘要与请求客户；不含明文密码。不创建账单，不改资金、账期、续费价、原商品快照或资源绑定。

Worker 发送前重新读取上游能力并比对摘要，并通过 `/provision/default` 的 `func=status` 确认原资源处于 on/off 空闲状态；已有上游任务时不发送破坏性请求。只允许首次 running 发送一次，租约接管一律 investigating，只读、不重发。响应 200 表示已受理，进入正常自助跟踪，不把每次受理转人工。受理后立即尝试捕获执行状态，随后每 15 秒由 Worker 只读查询；不在 HTTP 请求内等待磁盘工作，也不伪造百分比。

### 自动结束与占用解除

驱动只以 `data.status=process` 且 `data.task_type` 严格等于字符串 `reinstall` 识别重装执行，不再解析中文 `des`。云端机器字段 `data.task` 经财务最小白名单投影为 task_type；缺失、错误类型、只有操作编号或中文提示均不作为执行证据。现网客户接口只返回 status/des，兼容补丁及结构化真机样本仍须部署验证，见 [上游补丁说明](../plugins/providers/zjmf/compat/README.md)。原任务须同时满足：本版空闲预检后明确受理（monitor version 1）、已持久观察到本次重装执行、后续查询返回 on/off、原资源 header 的账号／商品／Active／云类型仍匹配、当前用户名与密码非空有效、读凭据后再次查询仍空闲。满足时同事务加密回填凭据、记录 `reinstall_outcome=execution_ended` 并将原任务结束为 success，解除冲突占用；不改资源绑定、实例服务状态、账期、续费价或资金。

**success 在这个分支仅表示自动跟踪与同步流程结束，不证明系统重装成功、可启动或可登录。** 客户与后台必须显示 `execution_ended`：“上游执行已结束，新凭据已同步；请登录检查系统结果”。凭据标记 upstream_reported，不写入“已确认重装系统”，并清除可能已过时的上次已确认镜像。未来可信完成回执或管理员实证确认才投影 success／已确认系统并标记凭据 verified。本站不额外做 SSH 探测、不调用重置密码、不用固定延时或密码／镜像变化推定成功。

### 异常调查

响应丢失、执行后本地崩溃丢失受理记录、旧适配器任务没有本版预检证据、未捕获执行过程或查询失败，均继续只读原任务，不能根据当前 on/off 结案。已受理但尚未观察执行显示 accepted；执行中显示 executing；缺凭据显示 awaiting_credentials；受理后查询不可用显示 query_unavailable。无受理的未知提交显示 investigating。未决最长一小时后转持久人工核验；明确无法查询或驱动拒绝仍走原异常入口。租约到期不释放业务占用，任何分支不自动再次重装。

正常 accepted／executing 不再作为后台“异常关注”项；全部任务／investigating 筛选仍能查到，异常超时后进入待核验列表与既有告警。该查询状态机只证明可确认的执行事实：供应商可在本站之外手工操作资源，当前没有远端 operation ID，不能声称与外部操作完全隔离或取得最终成功回执。

## 凭据与人工回填

重装 pending/running/investigating 或 failed+MANUAL_AUDIT_REQUIRED 期间，原密码查看入口拒绝返回旧密码。管理员原任务入口只允许 investigate / fulfill / close_unexecuted，不开放重试、退款或新购取消。fulfill 要求原资源、旧执行令牌、实际完成证据、明确完成确认和已核实的新用户名／密码；新密码 AES-256-GCM 加密，仅更新 delivery 与 encrypted_password，同事务审计不存密码。普通支持人员不能读取或回填密码。close_unexecuted 须证实原请求未执行且没有延迟请求，解除占用但不改凭据。终态与旧 Worker 由执行令牌隔离。

驱动的 succeeded 默认要求可关联完成证据和核实的新凭据；例外代码 REINSTALL_EXECUTION_ENDED 仅用于上述完整生命周期观察，核心重查持久受理／执行检查点后同步 upstream_reported 凭据。不得把这个代码当成系统成功回执。
