# 通知配置页：独立分区与保存结果核对

## 本批范围

仅整理 `/admin/notifications`，分为“邮件配置”和“工单订阅”。普通开关、已保存摘要、本区反馈和保存入口前移；SMTP参数按需展开。沿用原超级管理员权限、两个PATCH、独立版本及同事务审计，无新表、迁移、Worker、通知场景、真实发信或M2工单启用。支付配置后台另批处理。

支持初次直接进入 `?section=mail` 或 `?section=tickets`；页面内切区不改URL，避免App的fullPath key重建。两个分区非懒加载，各自持有已保存基线、非敏感草稿、查询及提交状态。只读接口仍返回两区，但每次只将所核对的分区用于本区恢复，不能刷新另一分区的草稿、版本或起点。

## 保存与核对

提交固定本区草稿及原expected_version，提交中禁止本区编辑／重复保存。两区独立保存，不提交另一分区字段；工单每次提交均保留切换订阅期的明确二次确认。成功后只读获取本区当前值；409、丢响应或不可信返回也先只读核对，不自动PATCH。

当前版本已变化且公开值与本次提交一致时，可据当前事实收口，说明“当前值已匹配”，不把一次GET当作原请求的执行回执。当前值不一致时展示已保存值与本区草稿，由管理员显式选择采用当前值，或保留草稿、采用当前版本后重新确认；不能自动覆盖草稿或自动保存。原请求未知且版本未变化时继续阻断写入并允许再核对，不能据一次旧值读取判断请求未执行。可信业务拒绝可解除原请求不确定性，但仍先核对409的当前版本。

SMTP替换密钥的丢响应不能由password_configured证明成功；只读投影不回显密钥，须保留人工核验提示并显式采用当前版本，不自动再次替换。核对失败保留草稿、原版本和待核对提示。本区的核对、采用与放弃不操作另一区。这里仅提炼两个通知表单实际重复的版本核对逻辑，不建设通用实体页壳、恢复队列或持久化草稿副本。

## 草稿、密钥和离开

切区保留非敏感草稿；显示未保存／提交中／待核对状态。离页有未保存或未决结果时明确提示，允许管理员确认离开；F5不承诺保留浏览器内存草稿。

SMTP密钥默认保留、不回显、不进入URL、浏览器存储或日志。显式替换在独立密钥编辑区域完成，在该区域提供“保存邮件配置并替换密钥”，仍调用同一原保存逻辑。离开焦点／视口、关闭SMTP区域、切区、后台化、pagehide和路由离开均清除明文并恢复keep，明确提示未提交替换已清除。提交时先固定请求，再清输入；不因清除输入篡改已经发出的保存请求。密钥编辑时不从区域外隐式携带明文保存。

### 兼容、成本与未验证边界

因长表单查找和整体重载丢草稿而修正前端；受影响模块仅AdminNotificationSettingsView与通知专用useNotificationDraft。共享函数只承接两区重复的草稿／版本／核对判断，每次调用有独立状态，不形成全站框架或第二份持久事实。增加本区只读对照、显式采用及密钥区域保护；减少整体重载、互相覆盖及未知工单反复切期的风险。HTTP字段、权限、业务服务、CLI、审计、加密、27表和发送门禁不变，无迁移或Worker重启要求；摘要、原邮件契约、API指针、前端、治理规范与路线图同步。

浏览器后台事件与pagehide为模拟；390×450焦点／缩小视口不是iOS／Android真实软键盘、触控或其他浏览器验证。本轮未操作M2通知配置、重启邮件Worker或发送真实邮件，未重跑systemd演练。M2工单启用与真实收件继续按 [原专项](M2_TICKET_MAIL.md) 单独安排。下一批回到支付配置后台，仍以已有服务和实际重复结构为依据。
