## 本批范围与兼容

前一轮“离线留样计价验证通过”仅覆盖零初装费、100%倍率、无账号折扣的七组历史报价。本批把该验证落实为插件内计价器与可重复的只读对价入口，增加计价边界、完整支持条件和整组回退检查。**客户仍使用原在线 calculate／checkout；不是客户本地预览已上线，也不是定时刷新已完成。**

实现位于 `plugins/providers/zjmf/LocalPriceCalculator.php`、`PriceComparison.php` 和 CLI 装配 `compare.php`。核心不引用具体插件，不新增通用接口、表、迁移、调度、常驻进程或依赖。CLI 只加载 Composer 自动加载器，不启动 Laravel、不读取部署 .env、不连接业务数据库。私有连接参数只能经 stdin 提供，验证连接后调用现有驱动的配置与报价读取方法；不调用购物车结算、付款或资源操作。

不修改原客户核价、quote_token／商品编辑版本、原请求键恢复、账单与实例冻结价格或 Worker 预检。无 HTTP／前端／Worker 接入和重启要求。真实购买仍单独授权，389仅选品与只读报价，563零库存门禁保持。

## 支持条件与回退

计价器输入为私有临时信封：`{schema, fetched_at, currency:{id,code}}`。`schema` 是配置接口 data，fetched_at 为真实抓取时的 Unix 秒数；currency 是调用方确认的报价货币身份，不从任意第一行猜测。信封只在内存或私有验收材料中使用，本批不写 products.config_cache。

只有下列条件同时满足，才产生本地 first／recurring 两个金额：

- 快照结构完整，抓取时间不在未来，年龄不超过900秒（包含边界）。缺失、损坏、过期不以默认组合价格替代。
- CNY，货币ID明确，config_links与实际配置组逐一对应；基础与所有子项在所选周期均有且只有一条匹配货币／type／relid的价格记录。只接受非负十进制字符串、至多两位小数。缺失组／费用、重复记录、负数／禁用价、浮点JSON或更高精度一律回退，不能将其转成零元。
- 魔方代理 `api_type=zjmf_api`、`upstream_price_type=percent`，正倍率最多两位小数且不超过1000%；无账号折扣（flag严格为false）、税、按日折算或次月合并；预付、周期商品。其他价格政策不猜算，仍在线核价。
- 月付或年付；原驱动能完整描述的枚举、单父无环枚举联动和独立15／18整数数量；所有选择通过原 ConfigOptions 校验。价格矩阵检查覆盖本周期的全部可选子项，不能因当前未选中而忽略缺价；其他周期单独判定。
- 数量区间连续、无重叠，范围、步长和上下限例外沿原 IntegerQuantity／ConfigOptions；自定义字段、其他数量类型与未知依赖继续不支持。
- 最终首期及续费价均在原 Money 的正金额界限内；零价、溢出或运算异常不返回金额。

失败结果仅为 `supported=false, reason=...`，没有first／recurring，不存在部分计价、零价回填或复用其他组合价格。PriceComparison在所有本地失败情形调用一次完整在线报价；在线查询或协议失败时整次失败，不能反过来使用本地价格掩盖上游失败。

## 运算顺序与证据来源

源码依据为本机魔方副本 `app/home/controller/CartController.php::getTotal`（实际cart/get_total路由）、`getProductConfig`及`app/common.php::quantityStagePrice`。本机源码说明运算语义，不保证所有供应商部署版本一致，因此必须逐组合对价，不能由源码直接宣布真实上游全规则通过。

按一单一实例 qty=1：

1. 基础周期价与基础初装费分别加入首期；枚举加入所选子项周期价与初装费。
2. 15／18按已走过的区间累加周期费用，区间下界非零时使用包含端点的数量；下界0不额外计算“第0个”单位。数量0没有数量费或数量初装费。
3. 数量初装费只取当前区间，不累加之前区间初装费。续费只含周期费用。
4. 保留上游PHP数值转换及BCMath阶段：首期为 `bcsub(bcmul(total, multiplier/100, 2), 0, 2)`；续费为 `bcsub(bcmul(signal_price, multiplier, 2)/100, 0, 2)`。逐项首期累加前也有bcmul(...,1,2)，不能统一改成最后一次round。显式传scale，不改变调用方bcscale。

这是指定源码与PHP8.4的兼容算法，不是通用阶梯计价标准。计价器诊断hash包含算法版本、周期、币种、倍率、原投影表单及完整本周期价格矩阵。

七组减字段留样保存在 `tests/fixtures/zjmf-pricing-samples.json`，只保留公开计价字段、配置与报价金额，不含账号、凭据、链接或当前库存保证。389月付默认1／2 IP为257／297，低规格1／2 IP为38／78；563默认、2 IP、60Mbps为299／359／399。各组首期和续费相同，来源仍是前一轮历史读取。

## 对价入口

```bash
php plugins/providers/zjmf/compare.php --live < /private/path/pricing-input.json
php plugins/providers/zjmf/compare.php --saved < /private/path/pricing-replay.json
php tests/local_pricing.php
```

私有输入文件应0600且位于仓库外。`--live`输入：remote_pid、billing_cycle、config_options、currency及connection（endpoint、credentials.username／password，结构同原连接验证服务）。它重新获取快照，再调用原驱动完整preflightPrice；仅GET配置／登录与POST报价，不结算购买。CLI不是公开端点，也不能作为不可信客户提交任意URL的代理。

`--saved`输入：snapshot、billing_cycle、config_options，以及原upstream_quote、upstream_config_options、upstream_schema_hash；旧留样回放另显式提供原observed_at。该模式只验证可信留样间的一致性，不认证留样来源，不把旧数据标成当前新鲜报价。

输出仅有模式、观察时间、受支持的本地金额／诊断hash／规范选项、上游两类金额和状态；不输出原响应、连接地址、凭据或driver_context。异常只输出固定脱敏错误；原驱动仍仅记录阶段耗时。状态：

| 状态 | 含义 | 退出码 |
| --- | --- | --- |
| matched | 本地受支持，安全表单hash及两类金额一致 | 0 |
| online_only | 本地不支持，在线报价成功，明确整组回退 | 0 |
| mismatch | 首期或续费金额不一致，不自动修正规则或发布快照 | 2 |
| rules_changed | 安全表单规则不同（即使金额相同），应重新采样 | 2 |
| 固定脱敏错误 | 在线不可用、响应不一致或CLI输入非法，无报价 | 1 |

所有状态的权威来源均为upstream。matched只证明这个组合、周期、时刻相符，不证明全部组合、其他周期、未来报价或库存。

这里的两类金额均是上游成本，不是经过本地加价的售价；本批没有另写加价算法，销售路径仍复用原Money::markup及原加价版本校验。

## 指纹与后续接入门禁

本批不改CatalogService现有整份config_cache签名，也不写入刷新时间。新的pricing_hash仅为插件诊断，**不是客户确认令牌或商品编辑版本**，不允许拿它绕过原quote_token或业务门禁。

未来接定时刷新时，必须把成功核对时间和库存观察独立保存；现有原始schema里也含库存等观察字段，不能仅删除新增时间字段就宣称已完成语义版本分离。配置联动、数量范围／步长／区间、计价规则、生成规则、上游绑定与本地加价仍须受销售版本和并发检查保护；无内容变化的刷新不应使确认失效。保存检查版本，不能覆盖管理员并发编辑；历史订单、原请求键恢复与Worker再次预检继续保持。

定时刷新、客户本地预览、提交实时复核与变价重新确认属于后续接入批，不在本批启用。非零初装费和非100%倍率若只有隔离证据，不能记录为真实供应商已验。
