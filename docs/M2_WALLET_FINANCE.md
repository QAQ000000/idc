# M2 充值、钱包流水与后台资金查询

用户于 2026-11-08 确认进入第二批，沿用前端整理设计的公共布局。交付主线为充值到账 → 余额购买/续费 → 后台核清资金去向；退款仍人工办理，原 15 分钟代扣扫描保留。充值提前唤醒已由后续独立批次实现，当前边界见 [续费增量](M2_RENEWAL_CONTRACT.md#充值到账后的异步唤醒)；下方本批验收记录保持历史范围。

## 领域与结算边界

复用 users.balance、invoices、payment_records、transactions，27 表保持，无新增实体和 DDL。充值单 type=recharge、instance_id=NULL、无报价到期时间，不预留库存或创建实例。创建请求使用必填 request_key（16–48 位字母/数字/下划线/短横线），映射到既有 checkout_key 的 `recharge:` 命名空间；请求摘要包含用途和规范化金额。相同用户/键/金额重放返回原单，改金额返回 409。金额必须是正十进制字符串，使用现有 Money/BCMath 与数据库金额上限，不使用浮点。

充值继续原易支付付款接口，禁止余额给自身充值。回调先由插件验签并核实归属、CNY 和网关交易唯一身份；同事务落实收凭证、账单 unpaid→paid CAS、钱包入账和追加流水。正常用途为 wallet_recharge，不计消费、佣金，不插入 Outbox。取消后支付、独立额外实收、金额不符仍按 late_wallet_credit 幂等入钱包，保留父单状态；不把 cancelled 改回 paid，也不复活任何资源。

充值锁定原账单后锁钱包；云消费保留实例→账单→钱包顺序。创建只持用户及本次新账单，原键重放只读旧账单。已验签真实入款允许记入停用账户，停用仍禁止登录/支出；信任边界是服务器验签和持久支付尝试，客户端不能自报成功或调用入账方法。金额超过钱包容量等无法安全结算时事务回滚并向网关返回失败，保留原尝试、待重试/人工对账，不能确认成功却漏款。

新增入钱包流水复用 transactions.trade_no 关联实际 payment_records.trade_no；历史流水通过原幂等键（late_credit:pay_ID、pay_invoice:inv_ID）反查，既有记录不重写。账单与凭证不是同一粒度：一张已付或已取消账单可能还有多笔独立实收，查询需显示每笔凭证和实际钱包变化。

## 页面与接口

| 路由/API | 权限和行为 |
|---|---|
| /wallet；GET /api/v1/wallet | 本人余额、纯充值入口、分页钱包流水；不读取其他分户或他人信息。 |
| POST /api/v1/wallet/recharges | 本人创建独立充值账单；body amount/request_key。响应复用原账单 DTO，网络结果不明保留键重试，也可去原账单列表查找。 |
| GET /api/v1/wallet/transactions | 本人钱包流水分页，按 invoice_id/type 筛选；含实际收款关联编号，不暴露幂等键、原始报文或秘钥。 |
| /invoices/:id；既有 pay/cancel | 充值单支持易支付付款/取消，隐藏余额付款；到账以服务端账单、本人钱包流水和凭证确认，浏览器返回参数不结算。已取消且有迟到款时显示独立到账结果。 |
| /admin/finance | 仅当前启用 finance/super_admin；账单、收款凭证、钱包流水三个只读页签，按客户 ID/精确邮箱、账单、网关交易号、渠道和 UTC 时间范围分页筛选，参数保留 URL。 |
| GET /api/v1/admin/finance/{invoices,receipts,transactions} | 同上；时间分别按账单创建、凭证实际付款（未付按创建）、流水创建解释。钱包按网关过滤仅返回可关联该实收的流水，不扩展为同账单所有流水。 |
| /admin/finance/invoices/:id；GET 对应 API | 关联显示客户、原账单、分页实收凭证与钱包流水；不返回凭据、price_snapshot 或原始 payload，不提供改账/退款/删除操作。 |

所有列表有加载、空结果、失败/重试与分页；详情长交易号可换行，表格在自身区域滚动，390px/320px 不造成整页横向溢出。账单首次到账与独立额外入款分开展示；钱包余额是当前可用值，历史 balance_after 不能当当前余额。页面不新增自动退款、充值赠送、营销、人工改余额或实时通知机制。
